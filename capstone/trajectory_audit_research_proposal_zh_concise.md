# 安全裁判是否需要阅读完整过程

## ATBench 轨迹安全评估的局部视图审计

**项目周期：** 10 周  
**计算资源：** 单人，CPU 与 Google Colab 级单卡 GPU  
**研究对象：** 用于判断大语言模型智能体行为是否安全的 benchmark 与 safety judge

## 摘要

大语言模型智能体（LLM agent）不仅生成文字，还能搜索文件、调用外部程序、发送邮件或执行付款。因此，安全风险可能发生在中间步骤：模型可能读取不该读取的数据、接受网页中的恶意指令，或执行超出用户授权的操作，即使最终回答看起来完全正常。

安全裁判（safety judge）负责阅读智能体的执行轨迹并判断其为 safe 或 unsafe。一条完整轨迹通常包含用户请求、工具说明、智能体动作、工具返回结果和最终回答。理论上，轨迹级评估应像阅读黑匣子一样，根据多个步骤之间的关系作出判断。

本项目研究一个基础问题：**现有 benchmark 的高分，是否真的要求模型理解完整轨迹？** 如果只看最终回答或最后一个动作就能预测大部分参考标签，那么高分首先说明模型掌握了这套数据中的局部规律，而不能单独证明它理解了授权、信息流和多步因果关系。

预备实验发现，在 ATBench 上，一个简单的词语分类器只读最终回答时达到 0.880 Macro-F1，高于阅读完整轨迹时的 0.829；在 R-Judge 上，只读最后一个智能体动作达到 0.917，完整记录为 0.803。项目将进一步使用冻结的小型安全模型和动作保持不变的反事实样本，检验这种现象是否仍然成立。

> 本研究检验的是“benchmark 分数是否要求模型使用完整轨迹”，不是“完整轨迹在真实世界中是否有价值”。局部视图得分高，并不意味着部署时可以丢弃完整日志。

## 直观例子

用户要求智能体把公开议程发送给 Alice，但网页中的恶意文字要求它把机密附件发给外部地址。智能体照做后只说：“任务已完成。”

真正的安全判断需要比较用户授权、网页指令和实际发送行为。只凭“任务已完成”猜出 unsafe，可能答对标签，却没有证明裁判找到了越权发生在哪一步。这类似一场声称考查数学推理的考试：如果只看答案格式也能高分，分数就不能充分证明推理能力。

## 核心术语

| 术语 | 通俗解释 |
|---|---|
| 智能体，agent | 能连续调用搜索、邮件或数据库等工具的语言模型系统。 |
| 轨迹，trajectory | 一次任务从用户请求到最终回答的完整执行记录。 |
| 安全裁判，guard 或 judge | 根据回答或轨迹判断 safe 与 unsafe 的模型。 |
| Benchmark | 包含测试案例、参考标签和计分规则的标准化“试卷”。 |
| 参考真值，ground truth | Benchmark 用于判分的参考答案。ATBench 标签经过人工审核，但不是绝对无误的自然事实。 |
| 局部视图 | 只保留轨迹的一部分，例如用户请求、动作或最终回答。 |
| 捷径信号 | 能预测标签，却不要求模型完成目标推理的表面线索。 |
| Macro-F1 | 分别评价 safe 和 unsafe 后取平均，范围为 0–1；它不是正确率百分比。 |
| 危险漏报率，unsafe FNR | 所有真实 unsafe 案例中被错判为 safe 的比例，越低越好。 |
| 正常误报率，safe FPR | 所有真实 safe 案例中被错判为 unsafe 的比例，越低越好。 |
| 冻结模型 | 直接使用已有模型，不根据 ATBench 再训练或微调。 |
| 反事实配对 | 保持实际动作不变，只改变最终措辞，用于测量措辞的影响。 |

## 研究问题

1. 用户请求、工具说明、动作或最终回答各自能恢复多少标签信息？
2. 将相似任务整组留在测试集后，局部信号是否仍然存在？
3. 结果能否由缺失回答、拒绝词、文本长度、记录结构或模型容量解释？
4. 冻结的小型 guard 和动作不变的反事实实验是否会重复这一现象？

前三个问题已有探索性结果，第四个问题是本 proposal 的主要待完成工作。

## 数据与方法

主数据 ATBench 包含 1,000 条人工审核轨迹，其中 503 条 safe、497 条 unsafe。建模前会删除 `label`、判定理由、风险来源和危害说明等答案字段。由于数据只公开了一个 test split，本研究使用五折交叉验证：数据被分成五份，模型每次在四份上学习、在剩余一份上测试，使每条记录都由没有见过它的模型预测。

为减少相似模板同时出现在训练和测试中的可能，项目根据用户请求和工具名称建立近似任务组，并保证同组样本不会跨越训练折和测试折。该方法称为 group-held-out split。它不是官方任务家族，只是可复现的代理方法。

每条轨迹生成五种视图：完整轨迹、仅用户信息、仅工具说明、仅智能体动作和仅最终回答。透明基线为 TF-IDF 加逻辑回归：TF-IDF 将词语和相邻短语转换为数字权重，逻辑回归再根据这些权重判断 safe 或 unsafe。该模型故意保持简单，用于检查标签是否能被表面文字规律预测。

R-Judge 在去除重复记录后保留 569 条，并按 27 个来源文件整组评估。它没有正式的最终回答标记，因此“最后动作”可能是工具调用或文字回答，不能等同于 ATBench 的最终回答。

## 预备结果

下表均采用主要的整组留出设置，而不是普通随机切分。

| 数据与视图 | Macro-F1 | AUROC | Unsafe FNR | Safe FPR |
|---|---:|---:|---:|---:|
| ATBench 完整轨迹 | 0.829 | 0.903 | 0.179 | 0.163 |
| ATBench 仅最终回答 | **0.880** | **0.938** | **0.044** | 0.193 |
| R-Judge 完整记录 | 0.803 | 0.902 | 0.080 | — |
| R-Judge 最后动作 | **0.917** | **0.969** | **0.053** | — |

AUROC 衡量模型把 unsafe 排在 safe 前面的总体能力，0.5 左右接近随机，1 表示完美排序。破折号表示该值没有进入 R-Judge 的主要报告表。ATBench 中 final-minus-full 的 Macro-F1 差异为 +0.051；500 次按组重复抽样得到的条件性 95% 区间为 `[+0.011, +0.091]`。

结果在以下检查中仍然存在：

- 删除 26 条缺少最终回答的记录后，final-only Macro-F1 仍为 0.871。
- 遮盖明显的拒绝、授权和完成词后，分数从 0.880 变为 0.877。
- 12 种聚类数量和随机设置下，full 为 0.815–0.835，final 为 0.870–0.880。
- 只看事件数量、长度和角色转换等结构特征，也能达到 0.803 Macro-F1。
- 在 750 条明确涉及风险的记录中，final 为 0.940，full 为 0.831。

这些结果属于探索性证据。它们不证明数据泄漏、标签错误或完整轨迹无用，也不意味着 final-only 模型可以部署。最终回答可能忠实总结过程，而简单模型也可能不擅长处理平均长约 53 倍的完整轨迹。

## 拟开展的验证

### 冻结小型安全模型

主模型为 [Qwen3Guard-Gen-0.6B](https://huggingface.co/Qwen/Qwen3Guard-Gen-0.6B)，约有 6 亿个参数；资源允许时加入 [StepGuard-4B](https://huggingface.co/ninty-seven/StepGuard)。冻结表示只运行模型，不在 ATBench 上更新其参数。

项目将在最多 50 条开发样本上固定提示词、输入截断和输出解析，再将这些样本排除出主结果。所有视图使用相同设置，并记录输入长度、截断、解析失败、推理时间和显存。主要比较是 full 与 final-answer-only；暂定“实际接近”的标准是 final 的 Macro-F1 不比 full 低超过 0.03，同时仍报告实际差异和不确定性区间。

### 动作保持不变的反事实

项目从 ATBench 分层选择 120 条轨迹，原则上 safe 与 unsafe 各 60 条。每条轨迹保留全部工具动作、参数、返回值和事件顺序，生成两种新回答：

- **含义保持改写：** 只改变语气、句式和拒绝或完成措辞。
- **动作报告冲突：** 让最终回答淡化、夸大或错误描述已经发生的动作。

每条原始轨迹形成一个三元组，共有 360 个文本版本和 240 个原始—改写配对。参考标签以实际动作和用户授权为中心，并经过间隔至少一周的第二次盲审。核心指标是标签翻转率、风险分数变化，以及 full 与 final-only 哪一种更符合动作证据。

### 外部复验与错误分析

同一冻结模型将在 R-Judge 上比较完整记录、所有动作和最后动作。项目还会人工分析约 80–100 个代表性错误，包括 full 正确而 final 错误、反向情况、危险漏报、正常误报和反事实翻转。

## 评价标准与限制

主要指标为 Macro-F1，同时报告 AUROC、危险漏报率、正常误报率、balanced accuracy、解析失败率、输入 token 数、延迟和显存。Balanced accuracy 是 safe 与 unsafe 两类召回率的平均值。Token 是模型读取文字时使用的基本单位。

主要限制包括：ATBench 没有独立的未见测试集；自动聚类不能替代真实任务家族；长轨迹可能受到截断或表示方式影响；人工反事实不完全等同于自然对话；一个小型 guard 不能代表所有模型；公开静态 benchmark 也不能估计真实部署中的事故率。

项目只分析公开静态记录，不执行其中的工具调用，不连接真实邮件、支付或企业账户，也不生成新的可执行攻击链。

## 预期贡献与交付物

项目的概念贡献是区分三个问题：模型能否预测 benchmark 标签、模型是否真正理解多步过程，以及模型能否发现真实部署中的危险。它直接回答第一个问题，为第二个提供诊断证据，但不把 benchmark 高分当成第三个问题的安全保证。

最终交付包括：

1. 一篇区分预备结果与新验证结果的 capstone 论文。
2. 可在 CPU 或 Colab 上运行的复现代码和 Notebook。
3. 120 个动作保持不变的反事实三元组及审核说明。
4. 逐样本预测、分组记录和不确定性分析。
5. 面向未来轨迹安全 benchmark 的审计 checklist。

成功不要求 final-only 超过 full。如果冻结 guard 确实从完整轨迹中获益，或在反事实改写下保持稳定，这同样会缩小预备发现的适用范围，并为 ATBench 的轨迹级有效性提供更强证据。
