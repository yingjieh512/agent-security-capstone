## 策略与比较对象

一次发送只有一个 SMTP 信封收件人。邮箱接受发送后，派发前必须有该收件人的有效批准，且实际提交的每份 MIME 解码附件都须在批准范围内。授权按内容字节和获批份数生效，允许只用其中一部分。改名、换序和修改正文均不影响授权。邮箱接受指本地 Mailpit 已持久化。附件数为零仍需检查收件人。审批写入明确无授权和没有取得审批回执是两种不同的输入。

1. 原封不动运行冻结 CLI，检查能否直接编译这个新策略。额外诊断可将排序后的整袋附件编码进旧的正文字段，测旧等值策略在新任务上的错判。
2. 在冻结程序之外，给有界搜索器提供源端字段菜单、授权谓词和有限执行世界，测试是否选出充分配置，并为不足配置生成可复查的异判同观察反例。逐一移除强手写基线的四项字段。只声称在声明的候选菜单、观测等价关系与信任假设下的最小性。
3. 将生成配置、封存的强手写配置、完整明文、元数据、整袋标签和两种投递端遗漏配置用于同一批 SMTP 发送。为文献中的计数投影另给一个保留精确收件人比较能力的对照。决策允许返回证据不足。未知计入分母。
4. 审批来自派发前独立保存的快照。取证读取 Mailpit REST，经 SMTP 分配的队列 ID 绑定操作。参考判定读取 Mailpit 已提交的原始 MIME，用另一套解析器和完整授权数据做逐项比较。主判定器不读真值。二条路径共用 Mailpit 的权威 SMTP 信封信息。

## 案例与指标

从仓库已固定版本的 ATBench send_email 和 Claw gog gmail send 中各取正文最短、最长的合格单收件人调用。仅使用四个正文长度构造合成正文，在四个模板上重复同一组场景。地址、附件和授权均为本实验生成。固定 18 个场景为相等、合法子集、同名同大小换内容、合法改名、换序、重复份数刚好、重复超量、等总数但份数分配错误、空对空、非空批准空投递、零附件错收件人、无审批且发送、可见 To 错而信封正确、可见 To 正确信封错、正文改变、零字节文件、较大授权袋的合法子集、较大授权袋的违规子集。不用这些投递或参考标签选配置。

主指标为正确确定数 / 全部受控投递、错误放行、错误指控和未知数。隐私指标分开计原始收件人、正文、文件名及可恢复附件内容的逻辑字节，并测两个完整认证信封的紧凑 JSON 字节。相等和份数也是披露。文件大小及正文长度影响字节节约。在生成配置上另外删除来源、篡改字段、跨操作重放与替换来源键，检查回执是否被拒。导出聚合计数和抽象反例，密钥和原始邮件不导出。

冻结版通过新策略才可称零修改迁移。扩展若无错地追平强手写、能区分遗漏与冗余、有邮箱端可复验反例，则支持继续做系统。要主张优于人、或对下一种未知策略可迁移，还要另行独立留出验证。
